Audio Session API

Lets a page say what kind of audio it plays through navigator.audioSession.type, and reports what the OS did to the page's audio through navigator.audioSession.state. It logs this event:

  • statechange on navigator.audioSession – state changed between inactive, active, and interrupted (for example a phone call or another app taking audio focus).

Pick a type, then play audio or start the microphone to make the session active. Interruptions are easiest to test on iOS or macOS Safari.

Debug version: add ?debug=1 to the URL (or click the bug chip above) to write detailed logs to the DevTools console: support checks, every type change, every raw statechange event with its full state, and audio and microphone actions. Open the console with F12 or Ctrl+Shift+J (Cmd+Option+J on macOS).

We found no official Chrome statement. These are the most relevant facts and discussions:

  • Not implemented in Chromium. There is no Chrome Platform Status entry for the API and no navigator.audioSession in Blink, so no flag turns it on. Browser support (MDN): Safari 16.4+ on macOS and iOS, Firefox Nightly only, Chrome and Edge no. MDN compatibility table
  • What "Firefox Nightly" means. Nightly is Firefox's daily development build, similar to Chrome Canary. The API exists there but hasn't shipped in any released Firefox, so regular Firefox users don't have it. MDN doesn't say whether Nightly also needs an about:config setting, and marks the API as experimental. For testing today, Safari 16.4+ is the only released browser with the API.
  • Audio focus on desktop. In w3c/audio-session#12, "Audio focus enforcement on desktop platforms" (2023), a Chrome media engineer notes that Chrome on desktop deliberately does not enforce audio focus, because desktop users multitask and don't expect one tab's audio to stop another. Types such as transient-solo assume that kind of enforcement. The issue is still open.
  • Related work that did ship. Chrome shipped the AudioContext "interrupted" state, which lets the browser report OS interruptions on Web Audio, one of the problems this API also addresses.

Controls

Play audio loops far_end_speech.wav in an <audio> element. Start microphone calls getUserMedia({audio: true}); with type auto, Safari may switch the session to play-and-record. Both work in every browser, but only change state where the API exists.
