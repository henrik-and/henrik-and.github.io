MediaStreamTrack muted

Shows the three track states on a microphone track from getUserMedia(), and on the received track of an optional WebRTC loopback. It logs these events:

  • mute / unmute on the track – the source temporarily can't provide audio (muted), for example an OS or hardware microphone mute.
  • ended on the track – the source is gone for good (readyState ended), for example the microphone was unplugged.
  • devicechange on navigator.mediaDevices – a device was added or removed, logged for context.

Start the microphone, then press the hardware mute key or mute the microphone in the OS, unplug a USB microphone, or click Disable track to compare with the app-side enabled switch.

Controls

Disable track sets track.enabled = false: the app's own mute. The track sends silence, but muted stays false because the source still works. The loopback sends the track from one RTCPeerConnection to another on this page so you can see the received track's states.

A received track starts muted, unmutes on the first RTP packet, and mutes again only when renegotiation stops reception: try Stop sending (renegotiate). Disabling the microphone track above makes this waveform flat too, but the received track stays muted = false, because RTP with silence still arrives. The getStats() section separates the cases: no RTP (no packets), RTP with silence (packets but no level), and RTP with audio. Stats are read once per second while the loopback runs.
