Idle Detection API

Uses an IdleDetector to report whether the user is active and whether the screen is locked. It needs the idle-detection permission and logs this event:

  • change on the IdleDetector – userState (active / idle) or screenState (unlocked / locked) changed.

Click Request permission, then Start detector. Leave keyboard and mouse alone for longer than the threshold, or lock the screen (Win+L, Ctrl+Cmd+Q on macOS), to see events. DevTools can also emulate the state (Sensors panel, "Emulate Idle Detector state").

Debug version: add ?debug=1 to the URL (or click the bug chip above) to write detailed logs to the DevTools console: support checks, permission requests and results, start() calls, every raw change event with its full state, and visibility changes. Open the console with F12 or Ctrl+Shift+J (Cmd+Option+J on macOS).

Controls

IdleDetector.requestPermission() must be called from a click. start() rejects a threshold below 60 000 ms. Stop uses an AbortSignal.

    Knowing when a user is idle or has locked the screen can reveal habits and help link visits across sites. The spec limits this with a permission, a minimum threshold of 60 seconds, and the idle-detection permissions policy. Chrome ships the API; Firefox and Safari don't.
