Network Information API

Reads the browser's estimate of the current connection through navigator.connection, and logs these events:

  • change on navigator.connection – any of effectiveType, downlink, rtt, saveData, type, or downlinkMax changes.
  • online / offline on window – related events from navigator.onLine, logged for context.

To see events, switch networks, turn Wi-Fi off and on, or pick a throttling preset in DevTools (Network panel).

    info

    The spec reduces precision to limit fingerprinting: downlink rounded to 25 kbit/s and rtt to 25 ms. Chrome is coarser: 50 kbit/s and 50 ms steps, capped at 10 Mbit/s and 3 s, with a fixed per-site random factor of 0.90–1.10. When it has no estimate yet, Chrome reports rtt 0 and downlink 10. downlink rounding and rtt rounding show the coarsest step that all values seen fit. Chrome exposes type (for example wifi), downlinkMax, and typechange by default only on Android and ChromeOS. On Windows, macOS, and Linux, enable chrome://flags/#enable-experimental-web-platform-features (copy it into the address bar) and relaunch Chrome; see which APIs need the flag. On desktop, Chrome reports type unknown unless every active network adapter has the same type, Hidden adapters count too: on corp Windows, Wi-Fi plus the Microsoft IP-HTTPS Platform Interface (a DirectAccess tunnel, adapter type 131) gives unknown rather than wifi. To list the adapters Chrome considers, run in PowerShell: $ifs = Get-NetIPAddress -AddressState Preferred | Select-Object -ExpandProperty InterfaceIndex -Unique; Get-NetAdapter -IncludeHidden | Where-Object { $_.Status -eq 'Up' -and $ifs -contains $_.ifIndex } | Format-Table Name, InterfaceDescription, InterfaceType. The values are estimates from recent traffic, not a speed test. Only Chromium-based browsers ship this API.
