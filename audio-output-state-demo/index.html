navigator.audioOutput (prototype)

Shows if audio played by this page would be heard on the selected speaker, and roughly how loud. Windows sets this with the speaker volume and Chrome's own volume in the Volume mixer. It is the same whether or not anything is playing. It logs these events on navigator.audioOutput:

  • mute / unmute – muted changed: the device or Chrome's Volume mixer row was muted or unmuted, or a volume went to zero.
  • change – state (audible, quiet, muted, unknown) or level (10 dB steps) changed.

Chrome checks the OS values about once per second, so an event can arrive up to a second after you move a control.

Device and player

Use this device calls setSinkId() on the player and on navigator.audioOutput, so what you hear and what the page reports describe the same device. Playing is not needed for the state. The page volume scales the samples in Chrome and does not change state or level.

    Find the matching Chrome log lines

    Start the build with --user-data-dir=C:\tmp\cr-audioout --enable-blink-features=AudioOutputState --enable-logging --vmodule=media_stream_manager=1, then run this in PowerShell. Chrome writes one line per change with all raw values (device dB and mute, Chrome's session volume, mute, and per-channel volumes) and the resulting state and level.

    Select-String -Path C:\tmp\cr-audioout\chrome_debug.log -Pattern 'AudioOutputState:' | Select-Object -Last 10 | ForEach-Object { $_.Line }
    info

    The state covers only what Windows and Chrome do to the signal (device volume and mute, Chrome's Volume mixer row, and Chrome's hidden per-channel volume), not the speaker hardware.
