Find the matching Chrome log lines

Start the build with --user-data-dir=C:\tmp\cr-sessvol --enable-logging --vmodule=media_stream_manager=1, then run this in PowerShell. It shows the constructor line (device name, params, role) and the session line of each stream; both carry the same WAOS[id=...]. 

Select-String -Path C:\tmp\cr-sessvol\chrome_debug.log -Pattern 'WAOS\[id=.*(WASAPIAudioOutputStream\(|LogAudioSessionVolumes)' | ForEach-Object { $_.Line }

UMA histograms (Windows, needs a build with CL 8830670)

Open chrome://histograms/#Media.Audio.Output.Win.Session in a new tab (paste it into the address bar) and reload that tab after each test step. Each histogram gets one sample each time Chrome opens an output stream, i.e. once per new LogAudioSessionVolumes log line. A Create & play that reuses the previous stream (see the countdown) adds no sample.

Media.Audio.Output.Win.SessionVolumeState Every opened shared-mode stream 0 Default (all 1.0, not muted) · 1 Muted · 2 Session volume reduced (mixer slider) · 3 Channel volume reduced (hidden in the mixer) · 4 Both reduced · 5 Query failed
Media.Audio.Output.Win.SessionAttenuationOfQuietestChannel Only when the state is 2, 3 or 4 Attenuation of the quietest channel in whole dB (0 = less than 0.5 dB, 100 = 100 dB or more)
Media.Audio.Output.Win.SessionChannelVolumesUnequal Only when a channel volume is below 1.0 (state 3 or 4) false = all channels reduced equally (likely saved state) · true = channels differ (balance-like)
